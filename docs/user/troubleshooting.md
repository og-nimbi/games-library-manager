# Troubleshooting

This guide covers common issues and practical fixes for Games Library Manager.

## Before troubleshooting

- Restart the app after changing settings (library root, launcher paths, shortcut folders, credentials).
- Confirm you are using the current C# desktop app build.
- Do not share API keys or secrets when posting logs/screenshots.

## App does not start or closes immediately

### Possible causes
- Missing WebView2 Runtime
- Missing/corrupted runtime DLLs in the app folder
- Unhandled startup error

### What to check
- Install or repair the **Microsoft Edge WebView2 Runtime**.
- Verify required files exist near `GamesLibraryViewer.exe`:
  - `WebView2Loader.dll`
  - `Microsoft.Web.WebView2.Core.dll`
  - `Microsoft.Web.WebView2.WinForms.dll`
- Check for `crash.txt` in the app/base directory or library output locations (if generated by the build you are running).
- Run the app from a writable location and ensure the library root is accessible.

## Blank window or UI does not load

### Possible causes
- WebView2 initialization failure
- Generated UI files missing or inaccessible in `<LibraryRoot>\_library`
- File access/path issues

### Fixes
- Confirm `<LibraryRoot>\_library\index.html` exists after a scan/build.
- Ensure the library root path is valid and writable.
- Restart the app to regenerate `_library` content.
- Temporarily try a simple local library root (e.g. `D:\Games`) to rule out permission/path issues.

## No games appear

### Possible causes
- Supported storefront clients are not installed or have no detected games
- Storefront data locations are unavailable
- Scan completed but results were empty

### Fixes
- Verify the storefront client (Steam/itch.io/Epic) is installed and contains installed games on this machine.
- Launch the storefront client once to ensure its local library/manifests are initialized.
- Restart the app to trigger a fresh scan.
- Check provider-specific expectations:
  - **Steam:** installed games and local Steam configuration must be discoverable
  - **itch.io:** games installed via the itch app
  - **Epic:** installed titles with valid Epic manifests

## A specific storefront is missing

- Confirm the storefront is currently supported by the C# app (Steam, itch.io, Epic Games).
- If supported but missing, verify the client is installed and detectable in standard locations.
- For launcher tiles specifically, add a **manual launcher executable path** in Settings as a fallback.

## Launcher tile shows "not found" or does not open

### Possible causes
- Auto-detection could not locate the launcher executable
- Stored override path is stale or incorrect

### Fixes
- Open **Settings > Launcher executables** and add/update the launcher path.
- Use the full path to the executable (e.g. `...\steam.exe`, `...\itch.exe`, `...\EpicGamesLauncher.exe`).
- Save settings and restart the app to rebuild launcher mappings.
- Verify the executable exists and can be launched manually from Windows.

## Game launches fail

### Possible causes
- Target path/shortcut/protocol is invalid or no longer exists
- Storefront client is not installed or not ready
- Permissions or anti-cheat/launcher prerequisites block startup

### Fixes
- Try launching the game directly from its storefront client.
- Confirm the game is still installed.
- Re-run the app to refresh generated shortcuts/targets.
- If using native library shortcuts, verify the shortcut target in the provider folder under your library root.

## Missing covers or metadata

### Possible causes
- No provider/store metadata available
- External enrichment source requires credentials
- Network issues or third-party service limits/blocks
- Cache contains stale/incomplete entries

### Fixes
- Add/configure API keys in **Settings** (IGDB, SteamGridDB, Steam Web API as applicable).
- Restart the app to rerun enrichment.
- Check network connectivity and retry later (third-party services may rate-limit or change behavior).
- If artwork appears corrupted/stale, close the app and remove affected files in `<LibraryRoot>\_library\artwork\`, then relaunch.

## Settings are not saved

### Possible causes
- App host bridge message not processed
- User profile/local app data path not writable
- UI changes saved but app not restarted

### Fixes
- Click the relevant **Save** button in Settings and wait for confirmation.
- Verify `%LOCALAPPDATA%\GamesLibraryManager\` is writable.
- Check for `settings.json` updates in `%LOCALAPPDATA%\GamesLibraryManager\`.
- Restart the app to apply changes that require rebuild/reload.

## API keys appear to be lost

### Possible causes
- Secrets are stored per Windows user via DPAPI and were created under a different profile
- `secrets.dat` was deleted or inaccessible

### Fixes
- Re-enter keys in Settings while logged into the correct Windows user account.
- Ensure `%LOCALAPPDATA%\GamesLibraryManager\secrets.dat` is accessible.
- Remember that DPAPI secrets do not automatically transfer to another PC/user profile.

## Performance is slow on startup

### Possible causes
- First-time metadata/artwork downloads
- Large libraries
- Network latency or provider throttling

### Fixes
- Allow the first scan/enrichment pass to complete; subsequent runs should benefit from caching.
- Ensure a stable network connection if enrichment is needed.
- Reduce unnecessary remote lookups by keeping credentials/configuration only for services you use (where applicable).

## Collecting useful diagnostics (for bug reports)

Include sanitized details such as:

- Windows version and WebView2 Runtime version
- App version/build info
- Library root and affected providers
- Steps to reproduce and observed behavior
- Any `crash.txt` contents (remove personal paths/secrets if sensitive)
- Screenshots of the issue (without exposing API keys)

See [../../SUPPORT.md](../../SUPPORT.md) and [../../SECURITY.md](../../SECURITY.md) for reporting guidance.
